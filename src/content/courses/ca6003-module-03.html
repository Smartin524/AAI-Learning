Diagnostic: Relationship & Dependency Analysis｜为什么发生

本章图表 / 方法：诊断分析三步图（关系分析 → 根因 → 假设检验）；五种关系分析技术对照表（第 7–8 页）。

典型问题：时间序列里为什么有异常值？销量为什么涨 / 跌？哪些因素和结果有关？

三步：① 关系与依赖分析（变量之间怎么关联）→ ② 根因识别（结合领域知识和数据找主要原因）→ ③ 假设检验与验证（用统计检验确认证据是否支持解释）。

技术适合的数据捕捉的关系输出怎么读
Pearson correlation连续数值变量线性关联r 在 −1 到 +1；符号 = 方向，绝对值 = 强度
Spearman correlation有序 / 排名变量，或数值变量单调关联，不一定线性ρ 在 −1 到 +1，基于排名计算
Linear regression连续结果 + 一个或多个预测变量预测变量与结果的线性关系系数表示方向和结果的估计变化量
Polynomial regression结果与预测变量呈曲线关系用多项式项表示非线性关系捕捉直线拟合不了的弯曲
Feature importance已训练模型里的多个预测变量各特征对预测的相对贡献模型最依赖哪些变量（不是因果排名）

易错：Pearson ≈ 0 只说明没有线性关系，可能还有 U 形关系。Spearman 能抓“越大越大”的单调曲线，但抓不了 U 形。相关不等于因果（第四周细讲）。

Root Cause: Fishbone & 5 Whys｜根因分析五步

本章图表 / 方法：销售看板收入异常偏低：五步根因表、Ishikawa 鱼骨图（第 9–10 页）。

案例：销售看板显示过去 3 天收入异常低。

步骤要回答案例做法
1. Define the phenomenon发生了什么？在哪里、什么时候？看板过去 3 天收入异常低
2. Explore possible causes有哪些可能的解释？用鱼骨图按 Data、Process、People、Tools 四类列出原因
3. Investigate & determine为什么？反复追问5 Whys：晚间交易缺失 → 导入太早 → 之后没有刷新 → 工具 / 流程限制
4. Validate root cause证据支持吗？对比源系统和看板；核对交易到达时间和刷新时间
5. Remediate & follow up能修吗？修好了吗？增加晚间 / 增量刷新 + 完整性检查；持续监控
鱼骨课件里的原因
Data源数据缺少当天晚些时候的交易；交易记录不正确或不完整；门店 / 地区数据延迟到达；重复和错误
Process导入安排得太早（如 8:05 PM）；每天只导入一次；不检查晚到的数据；更新看板前不做完整性验证
People以为 8 点后数据就完整了；数据团队和业务团队缺乏沟通；分析师以为看板是最新的；监控和责任不足
Tools工具只支持批量导入（不能增量）；没有配置处理晚到数据；不能自动重跑；没有完整性告警

课件总结：鱼骨图找出可能原因 → 5 Whys 往深处追问 → 用证据验证根因 → 整改并跟进确认有效。

Hypothesis Testing & Validation｜假设检验

本章图表 / 方法：认知游戏能否提高注意力：五步检验；六种常用检验方法表（第 11–12 页）。

目的：判断观察到的效应是有统计证据支持的，还是可以用随机波动解释。

步骤做什么认知游戏例子
1. State hypotheses写出要检验的假设H₀：认知游戏不能提高注意力；H₁：能提高
2. Select a test按研究设计和数据选检验比较玩游戏前后的注意力分数
3. Calculate p-value看观察到的结果和 H₀ 有多相容p = 0.03
4. Make a decisionp 值和显著性水平 α 比较0.03 < 0.05 → 拒绝 H₀
5. Validate & interpret检查假设，判断改进是否有实际意义证据支持有改进；还要看改进有多大、是否稳定
方法用途课件例子
t-test比较两组 / 两种条件的均值玩游戏前 vs 后的注意力分数
ANOVA比较三组及以上的均值三种训练方法的分数
Chi-square test两个类别变量是否有关联房屋类型 vs 社区
Correlation test两个变量是否相关GrLivArea 和 SalePrice
Regression significance test预测变量是否和结果有关OverallQual 能否帮助解释 SalePrice
Non-parametric tests参数检验的假设（如正态）不成立时比较组Mann–Whitney U / Wilcoxon
  • p < α：拒绝 H₀，证据支持 H₁。
  • p ≥ α：不拒绝 H₀。这只说明证据不够，不等于证明 H₀ 是真的。
  • p 值不是“H₀ 为真的概率”，而是假设 H₀ 成立时，得到当前或更极端结果的概率。
  • 同一批人前后测用配对 t 检验，两批不同的人用独立样本 t 检验。
from scipy.stats import ttest_rel, ttest_ind, f_oneway, chi2_contingency, mannwhitneyu
ttest_rel(after, before)            # 同一批人前后对比（配对）
ttest_ind(group_a, group_b)         # 两批不同的人
f_oneway(method1, method2, method3) # 三组及以上 → ANOVA

目标：用从已有数据学到的模式，估计未知或未来的结果。流程：已有数据 → 用算法学习模式（拟合模型）→ 用到新数据 → 估计结果。

任务做什么学习方式课件例子

Prescriptive Analytics｜该怎么做

本章图表 / 方法：房屋改造推荐流程；规则、优化、决策树三种方法（第 14 页）。

目标：在考虑预测结果、成本和约束的情况下，推荐最好的行动。

流程：房屋现状（GrLivArea、GarageCars、OverallQual…）→ 用训练好的模型预测房价 → 列出可能的改造（加车库、扩面积、翻新）→ 用决策方法评估（预测涨价、成本、预算和空间限制）→ 推荐行动（加车库、扩面积或不改）。

方法原理房价例子
Rule-based固定的 IF-THEN 规则，可由专家定或从数据中得出IF 没有车库 AND 预算 ≥ $30,000 AND 空间足够 → 建议加车库
Optimization用数学方法在选项中找最优；包含目标函数、决策变量、约束在加车库、扩面积、翻新厨房中选择，使预测涨价最大，且总花费 ≤ $50,000
Decision trees一层层的规则 / 条件，逐步缩小选项直到得出推荐面积 < 1500 且没有车库 → 考虑加车库；否则预算有限 → 小翻新；否则 → 不改

House Prices · Five Questions｜同一份数据，五种问题

本章图表 / 方法：五个房价场景，每个按四种分析拆解（第 15–19 页）。

场景DescriptiveDiagnosticPredictivePrescriptive
1. 我想买房，该看什么？典型房价多少？按社区、面积、质量怎么变？为什么有些房子贵很多？主要是面积、质量、位置、房龄还是车库？给定房屋特征，预计能卖多少？按我的预算，该优先看哪些特征？
2. 找到一套便宜房，划算吗？类似房子的正常价格是多少？为什么便宜？更小、更旧、质量差还是社区不同？按它的特征，预期售价多少？按价格和预期价值，要不要买？
3. 买入、翻修、转卖高价房有哪些特征？哪些特征和高售价有关？翻修后能卖多少？买哪套、怎么翻修能让预期利润最大？
4. 开发商该在哪投资？哪些社区和房型历史价格更高？什么特征解释了社区间的价差？具有某些特征的新房能卖多少？在预算和约束下，开发 / 投资什么类型？
5. 银行要不要给这个人房贷？房产的历史价格和特征？哪些特征和价值高低有关？作为抵押物的房产预期值多少？按预测价值和贷款约束，可以给多少额度、什么条件？

预期利润公式（第 17 页）：Expected Profit = Expected Sale Price − Purchase Price − Renovation Cost − Other Costs

算一个：预期售价 500,000，买价 380,000，翻修 60,000，其他费用 30,000 → 利润 30,000。如果售价预测低估 10%（实际 450,000），利润变成 −20,000。预测误差会直接改变决策。

Notebook Supplement · PCA Dimensionality Reduction｜PCA 降维

本章图表 / 方法：8×8 手写数字；标准化；二维投影；累计解释方差曲线；2 / 10 / 20 / 40 个主成分重建图；64 维 vs 20 维逻辑回归对比。

一句话：PCA 把很多特征压缩成少数几个“综合特征”（主成分），尽量保留原始信息。主成分是原特征的线性组合，是数据中变化（方差）最大的方向；PC1 最重要，PC2 次之，彼此垂直。

  • 数据：1797 张 8×8 数字图片，每张 64 个像素 = 64 个特征。
  • 为什么先标准化：PCA 找方差最大的方向，数值范围大的特征方差大，会“抢走”主成分；PCA 还要求数据以 0 为中心。
保留主成分数210203040
累计解释方差21.6%58.9%79.3%89.3%95.1%
重建效果模糊、细节全丢能认出数字—接近原图
逻辑回归准确率训练时间
原始 64 维0.9800.04 秒
PCA 20 维（保留 80.8% 方差）0.9540.048 秒

结论：维度越少，压缩越强，信息丢失越多。准确率略降；Notebook 认为 PCA 的主要好处是训练时间，但这个小数据集上实测并没有更快。选多少个主成分，常见做法是找累计方差曲线的拐点，或设定目标（如保留 90%）。

pca = PCA(n_components=20, random_state=42)
X_train_pca = pca.fit_transform(X_train)   # 只在训练集上 fit
X_test_pca  = pca.transform(X_test)
pca.explained_variance_ratio_.sum()        # 保留的方差比例：0.808

保留 80% 方差不等于准确率 80%，方差是“信息量”，准确率要在带标签的测试集上算。Notebook 先在全数据上 StandardScaler 再划分，严格来说缩放器也应只在训练集上 fit。

Notebook Supplement · Trees & Imbalanced Classification｜三种树模型处理不平衡

本章图表 / 方法：two moons 非线性数据、只保留 10% 的类别 1；决策树、随机森林、XGBoost 的决策边界和分类报告。

数据：4000 个月牙形点（noise = 0.25），类别 0 全保留，类别 1 只留 10%，得到 2000 : 200；分层划分 70 / 30（测试集 600 : 60）。一条直线分不开两类，所以逻辑回归不适合。

模型处理不平衡Accuracy少数类 precision少数类 recall少数类 F1
决策树（max_depth=5）class_weight="balanced"0.9480.650.920.76
随机森林（300 棵，max_depth=6）class_weight="balanced"0.9710.840.850.84
XGBoost（400 棵，max_depth=4）scale_pos_weight = 负 / 正 ≈ 100.9560.760.750.76
模型特点
决策树用很多矩形逼近曲线，边界锯齿状；对噪声敏感，方差高，recall 提高但不稳定
随机森林每棵树用不同的 bootstrap 样本，局部过拟合各不相同，投票平均后边界变平滑，方差降低，准确率和 F1 更平衡
XGBoost树一棵接一棵训练，每棵新树专门纠正前面的错误；重叠区域的细小调整是纠错，不是过拟合

class_weight="balanced" 怎么算：weight_c = N / (K × N_c)，N 是总样本数，K 是类别数，N_c 是该类样本数。训练集 1400 : 140 时，少数类权重 = 1540 / (2 × 140) = 5.5，多数类 = 1540 / (2 × 1400) = 0.55，相当于少数类分错的惩罚是多数类的 10 倍。

scale_pos_weight：XGBoost 二分类的参数，把正类（少数类）的损失放大，常用经验值 = 负类数 / 正类数。

tree = DecisionTreeClassifier(max_depth=5, class_weight="balanced", random_state=42)
rf   = RandomForestClassifier(n_estimators=300, max_depth=6, class_weight="balanced", random_state=42)
xgb_model = xgb.XGBClassifier(n_estimators=400, max_depth=4, learning_rate=0.05,
                              scale_pos_weight=neg / pos, random_state=42)

这个 Notebook 不生成合成数据，而是通过调整模型的类别权重来处理不平衡，和第二周的 SMOTE 是两种思路。

自测

本章图表 / 方法：按考试常见题型整理，先自己答再展开。

1. 下面各属于哪种分析？a 上季度各地区销售额多少 b 为什么上季度销量下降 c 下季度能卖多少 d 预算内该投放哪个渠道

a 描述；b 诊断；c 预测；d 处方。

2. 两个变量是单调但非线性的关系，用 Pearson 还是 Spearman？

Spearman，它基于排名，能捕捉单调关系；Pearson 只看线性关系。Spearman 也适合有序（ordinal）变量。

3. 鱼骨图的四类原因是什么？“导入时间安排在 8:05 PM”属于哪类？

Data、Process、People、Tools。导入时间安排属于 Process；“工具只支持批量导入”属于 Tools；“以为看板是最新的”属于 People。

4. 根因分析五步的顺序？

定义现象 → 探索可能原因（鱼骨图）→ 深入调查（5 Whys）→ 用证据验证 → 整改并跟进。

5. 比较三种训练方法的平均分用什么检验？房屋类型和社区是否有关联呢？

三组均值 → ANOVA；两个类别变量的关联 → 卡方检验。

6. p = 0.08，α = 0.05，结论是什么？能说“证明了游戏无效”吗？

不拒绝 H₀。不能说证明无效，只能说证据不足。

7. 客户分群属于回归、分类还是聚类？它是监督还是无监督？

聚类，无监督（没有预设标签）。

8. 处方分析中优化模型包含哪三个要素？

目标函数、决策变量、约束（如预算 ≤ $50,000）。

9. 预期售价 600,000，买价 450,000，翻修 80,000，其他 20,000，预期利润是多少？

600,000 − 450,000 − 80,000 − 20,000 = 50,000。

10. PCA 前为什么要标准化？保留 20 个主成分得到 80% 方差，模型准确率就是 80% 吗？

PCA 找方差最大的方向，不标准化时数值范围大的特征会主导主成分，并且 PCA 要求数据以 0 为中心。80% 是保留的信息量，不是准确率（Notebook 中 20 维的准确率是 0.954）。

11. 随机森林为什么比单棵决策树稳定？XGBoost 和随机森林的训练方式有什么不同？

随机森林的每棵树在不同的 bootstrap 样本上训练，各自的过拟合不同，平均后方差降低、边界更平滑。随机森林的树是并行独立训练的；XGBoost 是顺序训练，每棵新树纠正前面的错误。

12. 训练集 900 个负类、100 个正类，class_weight="balanced" 时正类权重多少？XGBoost 的 scale_pos_weight 设多少？

正类权重 = 1000 / (2 × 100) = 5；负类 = 1000 / (2 × 900) ≈ 0.56。scale_pos_weight = 900 / 100 = 9。
