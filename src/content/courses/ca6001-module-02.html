What Is Reinforcement Learning?｜第三种机器学习

本章图表 / 方法：三种机器学习对照表；课本 / 交朋友 / 骑自行车类比（第 3–6 页）。

  • RL 是除监督、无监督之外的第三种机器学习。
  • 目标：学到最优策略（policy），让 agent 在环境中的累积奖励最大。

CartPole 是 OpenAI 的经典问题，被称为 RL 的 “hello world”。小车在无摩擦轨道上移动，目标是不让杆倒下，一轮最多拿 200 分。

  1. 定义 / 创建环境（真实或模拟）
  2. 设定奖励：奖励是 agent 的表现指标，往往要迭代几次才能定下来
  3. 定义 agent 和训练算法
  4. 训练和验证：调策略、让 agent 探索，可能很耗时耗资源
  5. 部署策略：确认最优策略后上线

RL Implementations and Algorithms｜三类方法和三种算法

本章图表 / 方法：Policy / Value / Model-based；Q-learning、SARSA、Deep Q-Network（第 14–15 页）。

类型做法
Policy-based直接优化策略（在某状态下采取什么动作）来最大化奖励
Value-based用价值函数（如 Q 表）估计各状态下各动作的潜在奖励，选最好的
Model-based先建立环境的内部模型，预测未来状态和奖励，再据此决策
算法特点
Q-learningOff-policy、model-free；Q 指动作的“质量”（quality）。更新时假设下一步取最优动作
SARSAState-Action-Reward-State-Action；On-policy，用实际执行的下一个动作来学习
Deep Q-Network (DQN)“Deep” = 用神经网络；把二维 Q 表换成神经网络，状态太多时也能算

Q-learning 更新公式（补充）：Q(s,a) ← Q(s,a) + α [r + γ·max Q(s′,a′) − Q(s,a)]。例：旧 Q = 2，r = 1，下一状态最大 Q = 4，α = 0.5，γ = 0.9 → 目标 = 1 + 3.6 = 4.6，新 Q = 2 + 0.5 × 2.6 = 3.3。

易错：on-policy / off-policy 不是“在线 / 离线”。区别在于学习时用的是实际执行的动作（SARSA），还是假设的最优动作（Q-learning）。

Exploration vs Exploitation & Discount Factor｜ε 和 γ

本章图表 / 方法：探索与利用、ε-greedy、贪心算法；折扣因子 γ；格子世界 V 值计算（第 16–20 页）。

概念含义
Exploration 探索尝试新动作，了解环境和动作-奖励关系，减少不确定性
Exploitation 利用用已有知识选当前看起来奖励最大的动作
ε-greedy概率 ε 随机选动作（探索），概率 1 − ε 选当前最好的（利用）
Greedy 贪心每步只选局部最优，计算快，但需要“先牺牲后收获”时会错过全局最优

ε-greedy 算概率：k 台机器、ε = 0.2 时，选中当前最佳的概率 = 1 − ε + ε/k（探索时也可能随机抽中它）。4 台机器：0.8 + 0.05 = 0.85；某一台非最佳：0.2 / 4 = 0.05。

折扣因子 γ（0 到 1）

  • 平衡眼前奖励和未来奖励（即时满足 vs 延迟满足）。
  • γ 越大越看重未来；γ 越小越看重眼前。
  • 折扣回报：G = r₁ + γr₂ + γ²r₃ + …。例：奖励 1、0、10，γ = 0.9 → 1 + 0 + 8.1 = 9.1；γ = 0.5 → 3.5。

格子世界：第一轮 V 值（第 18–20 页）

     1  2  3  4
row1  S  .  .  .
row2  .  #  .  .        # = 墙
row3  .  .  .  G(+10)

随机策略（上下左右各 0.25），每走一步奖励 −1，γ = 0.9。第一轮所有格子 V = 0，只有 G = 10。

V(s) = Σ 四个方向 0.25 × (−1 + 0.9 × 走到那格的 V)
撞墙或出界 → 留在原地
  • 不挨着 G 的格子：4 × 0.25 × (−1 + 0) = −1（课件图上老师标的都是 −1）
  • 挨着 G 的 (2,4) 和 (3,3)：3 × 0.25 × (−1) + 0.25 × (−1 + 0.9 × 10) = −0.75 + 2 = +1.25

课件勘误：第 19 页这个算式结果写成 −1.25，按式子算是 +1.25。考试时写出完整算式。

易错：① γ 只乘下一个格子的 V，不乘这一步的 −1；②“一轮”不是 agent 走一步，而是给每个格子都用旧 V 值算一遍；第二轮再用第一轮的结果。

Multi-Armed Bandit Problem｜多臂老虎机

本章图表 / 方法：赌徒选老虎机；ε-greedy 策略与 Q 值增量更新（第 21 页；Multi_Armed_Bandit_Problem.ipynb）。

问题：几台老虎机的中奖率各不相同且未知，赌徒想在多次拉杆中赢得最多。核心就是探索与利用的平衡。

更新公式：Q(a) ← Q(a) + (1/N(a)) × (R − Q(a))。Q(a) 是动作 a 的估计价值（平均奖励），N(a) 是选它的次数（先加 1 再更新），R 是这次的奖励。

算一个：某臂初始 Q = 0，三次奖励 1、0、1：

  • N = 1：0 + 1 × (1 − 0) = 1
  • N = 2：1 + ½ × (0 − 1) = 0.5
  • N = 3：0.5 + ⅓ × (1 − 0.5) ≈ 0.67，正好是平均奖励 2/3。这个公式就是“增量求平均”。

ε 保证每台机器都会被试到，不会因为一开始运气差而错过更好的机器。

Notebook：三台老虎机

真实中奖率 [0.2, 0.7, 0.4]，ε = 0.1，玩 1,000 轮。agent 不知道真实概率，只能根据拿到的奖励估计 Q。结果：估计的 Q 值接近真实概率，第 2 台（0.7）被拉的次数远多于其他两台，另外两台只在探索时被选中。

if rng.random() < epsilon:
    action = rng.integers(3)                         # 探索：随机选
else:
    action = np.argmax(q_values)                     # 利用：选当前最好
reward = int(rng.random() < true_probabilities[action])
counts[action] += 1
q_values[action] += (reward - q_values[action]) / counts[action]   # 增量平均

Reinforcement Learning with Human Feedback｜RLHF

本章图表 / 方法：RLHF 流程图；数据收集、监督微调、奖励模型三步（第 22–27 页）。

一句话：把人类反馈放进奖励函数，让模型的行为符合人的目标。是训练 LLM 的行业标准，让输出无害、真实、符合人类价值观。

  1. 收集数据：准备问题（如“NTU 的 HR 部门在哪？”），请专家写出准确自然的回答，组成问答对。
  2. 监督微调（SFT）：拿商用预训练模型（GPT、LLaMA、Gemini 等）作底座微调，可用 RAG 接入公司内部知识；和人写的回答比较相似度，越接近人类回答奖励越多。
  3. 训练单独的奖励模型：同一问题生成多个回答，人给回答排序；用这些偏好训练一个 reward model，它能自动估计“人会给几分”。
  4. 用奖励模型优化策略：LLM 内部评估多个候选回答，选预计奖励最高的。

为什么要单独的奖励模型：人工逐条打分太慢太贵，奖励模型能自动、大规模地给分。

Challenges, Future Directions & GRPO｜挑战与 DeepSeek

本章图表 / 方法：四个挑战和四个未来方向；DeepSeek R1 的 GRPO 公式（第 28–29 页）。

挑战未来方向
Sample efficiency：需要和环境大量交互Deep RL：结合神经网络，系统更独立灵活
Computation cost：训练耗资源Transfer learning：把旧技能用到新领域
Stability & convergence：有些算法（尤其神经网络）不稳定、难收敛Multi-agent RL：多个 agent 互动
Ethical concerns：医疗、金融等敏感领域的意外后果Robustness & generalization：学会多种技能

GRPO（Group Relative Policy Optimization）：DeepSeek R1 用的方法。同一个问题生成一组（G 个）回答，组内比较打分：比组平均好的回答，优势 Aᵢ 为正，提高它的生成概率。

  • 黄色（主要目标）：新旧模型生成该回答的概率比 × Aᵢ；奖励大时希望这个比值大。
  • 绿色（clip）：概率比离 1 太远就截断到 [1−ε, 1+ε]，防止一次改太多，保持稳定。
  • 蓝色（KL 正则项）：别离参考模型太远。

这里的 ε 是截断范围，不是 ε-greedy 的探索率。GRPO 用组内平均当基准，省掉了单独的价值模型。

Lyft Case｜派单时考虑司机的长期价值

本章图表 / 方法：Lyft 案例 3 页：问题、司机价值、switchback 测试、结果与局限、两司机三乘客练习。

旧系统的问题：每隔几秒把所有等车乘客和空闲司机配对，只看当下（如总接驾时间最短），不管行程结束后司机在哪。同样车费，一单终点在繁忙市中心，一单在深夜郊区，旧系统看不出区别。司机少时还会陷入 “wild goose chase”：接驾越远 → 完成单数越少 → 司机更少。

新思路：算每个位置和时间的司机价值（剩余班次预计能赚多少）。

匹配分 = 车费 + 终点的司机价值 − 司机当前位置的价值
RL 要素Lyft 里是什么
Agent每个司机
Action接这单 / 等待
Reward车费
Value function司机价值
  • 怎么学：每单结束后比较预期收入和实际收入，把估计往实际调。在线持续学习，全天候、每个城市都在跑（迈阿密跨年夜价值飙升后又回落）。DiDi 是离线从历史数据学。
  • 选简单模型：Lyft 认为深度网络对这么关键的系统“不够透明”，选了工程师能检查的简单模型。
  • 为什么不用 A/B test：两组共享同一批司机，新系统把司机安排得更好，对照组也受益，会低估效果。改用 switchback test：整个区域按时间段轮流用新旧系统；每次切换后市场要 2–3 小时稳定，所以时间块要超过 4 小时，并丢掉刚切换后的数据。
结果（2021 年推广到所有市场）变化
找不到司机的请求−13%
乘客取消−3%
五星评价+1%
额外收入每年 3,000 万美元以上（约占营收 1%），不额外花司机激励

案例没告诉我们的：去冷清地区的乘客是不是等更久（只报了总体结果）；系统只从自己选的行程中学习，可能永远发现不了被低估的区域（缺少探索）；司机发现规律后会改变行为；单次匹配很难向司机解释。

课堂练习：两位司机、三名乘客

A 在 Central（价值 $50），B 在 Riverside（$30）。R1：车费 $38 去远郊（价值 $8）；R2：$14 去夜生活区（$55）；R3：$16 从 Riverside 去 Central（$50）。接驾分钟：A→R1/R2/R3 = 2/3/9，B→R1/R2/R3 = 10/11/2。

匹配分R1R2R3
A（$50）38 + 8 − 50 = −414 + 55 − 50 = 1916 + 50 − 50 = 16
B（$30）38 + 8 − 30 = 1614 + 55 − 30 = 3916 + 50 − 30 = 36
  1. 旧系统（接驾总时间最短）：A→R1 + B→R3 = 4 分钟，R2 等待。
  2. 六个分数见上表。
  3. 新系统（总分最高）：A→R2 + B→R3 = 55 与 A→R3 + B→R2 = 55 打平；前者接驾 5 分钟、后者 20 分钟 → 选 A→R2 + B→R3，R1 等待。
  4. 放弃了什么、得到什么：放弃了最贵的一单（本轮车费从 $54 降到 $30）和 1 分钟接驾时间；换来 A 被送到高价值的夜生活区而不是困在远郊，后续收入更高。

Notebook 练习与自测

Notebook 题目思路与答案
Q1 格子世界：上面的 3×4 网格，γ = 0.9，随机策略，V(G) = 10，写出一轮后每格的 V 并解释不挨着 G 的格子都是 −1；(2,4) 和 (3,3) 是 +1.25。原因：第一轮只有一步之内能到 G 的格子“知道”附近有奖励
Q2 Safe / Risky：Safe 固定 +2；Risky 一半 +5、一半 −1；γ = 0.8，算三个序列的回报Safe(+2)→Safe(+2)：2 + 0.8 × 2 = 3.6；Safe(+2)→Risky(+5)：2 + 4 = 6.0；Safe(+2)→Risky(−1)：2 − 0.8 = 1.2；三者平均 3.6。Risky 期望奖励 = 0.5 × 5 + 0.5 × (−1) = 2，和 Safe 一样，但方差更大
1. RL 和监督学习最大的区别？

没有标签，只有奖励反馈；靠试错学最优策略，目标是长期累积奖励最大。

2. CartPole 有几个观测、几个动作？奖励怎么给？什么时候结束？

4 个观测（小车位置、速度、杆角度、角速度），2 个动作（左 / 右推）。杆每立住一个 timestep 得 1 分；杆倒、出界或满 200 步结束。

3. 用 Q 表记录每个状态下各动作的价值，属于哪类方法？

Value-based。

4. Q-learning 和 SARSA，哪个是 on-policy？

SARSA 是 on-policy；Q-learning 是 off-policy。两者都是 model-free。

5. 4 台老虎机、ε = 0.2，选中当前最佳机器的概率？

0.8 + 0.2 / 4 = 0.85。

6. 选项 A 第 1 步得 5；选项 B 前两步 0、第 3 步得 10。γ = 0.9 和 0.5 时分别选哪个？

B 的价值 = γ² × 10。γ = 0.9：8.1 > 5，选 B；γ = 0.5：2.5 < 5，选 A。

7. 格子世界中，四个邻格 V 为 0、0、2、10，随机策略、步奖励 −1、γ = 0.9，V(s) 是多少？

0.25 × [(−1) + (−1) + (−1 + 1.8) + (−1 + 9)] = 0.25 × 6.8 = 1.7。

8. 老虎机初始 Q = 0.5，这次拉完 N = 4，奖励 R = 1，新 Q？

0.5 + (1/4)(1 − 0.5) = 0.625。

9. RLHF 为什么要单独训练一个奖励模型？

人工逐条打分太慢太贵。用人类对回答的排序训练奖励模型，它就能自动、大规模地估计“人会给几分”，用来优化 LLM。

10. Lyft：司机在郊区（价值 $20），R4 车费 $25 去机场（$40），R5 车费 $30 去另一个郊区（$20），接哪单？

R4 = 25 + 40 − 20 = 45；R5 = 30 + 20 − 20 = 30。接 R4，虽然车费低，但把司机送到了热门地点。

11. Lyft 为什么用 switchback 而不是 A/B test？

两组乘客共享同一批司机，新系统的好处会溢出到对照组，A/B test 会低估效果。

12. “Lyft 系统只从自己选的行程中学习，可能永远发现不了被低估的区域”，这对应哪个 RL 概念？

Exploration vs exploitation：只利用、不探索，就拿不到新区域的信息。可以借鉴 ε-greedy 加入探索。
