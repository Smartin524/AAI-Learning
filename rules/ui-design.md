# AAI Learning UI 与设计规则

## 1. 设计哲学

AAI Learning 是一个面向持续学习的课程型知识手册，不是营销网站。界面应服务于三个目标：

1. 让用户快速选择正在学习的课程。
2. 让用户在长篇内容中保持方向感，知道当前章节、学习目标和下一步行动。
3. 让复杂概念通过清晰的层级、术语、例子和练习变得可检索、可复习、可验证。

整体风格遵循：克制、清晰、可信、可读。优先使用留白、排版和细边界建立层次，避免为了“看起来丰富”而增加装饰性卡片、渐变、徽章、统计数字或无意义的组件。

## 2. 信息架构

### 首页：课程选择

- 首页的唯一核心任务是选择课程。
- 首页标题使用随机开门语；每次加载播放一次逐字出现动画，句号使用品牌蓝色，并尊重 `prefers-reduced-motion`。
- 课程以居中的纵向列表呈现，不使用章节格子或卡片墙。
- 每个课程入口包含：编号、课程名称和极短的内容说明；不显示右侧箭头。
- 首页不放课程内章节列表、后续阶段说明、学习路线长文案或 RAG 相关宣传语。
- 首页不显示顶部课程切换菜单，避免与课程选择任务重复。

### 课程页：学习内容

- 课程页沿用章节阅读布局：左侧目录、右侧主内容。
- 左侧目录只用于当前课程内部导航，不用于常驻切换全部课程。
- 顶部“课程”按钮用于在不同课程之间切换；菜单默认关闭，点击外部区域后关闭。
- 当前课程在菜单中保持高亮。
- 每个课程可以先有一个 Module 1 页面，再逐步增加 Module 2、Module 3；不要为了凑齐数量创建空模块。

### 内容结构

每个 Module 或章节尽量按以下顺序组织：

1. 课程/章节标题与一句摘要。
2. 学完你应该能够（学习目标）。
3. 必须掌握的术语。
4. 核心知识。
5. 常见错误。
6. 练习。
7. 掌握标准或下一步。

## 3. 视觉规范

### 色彩

沿用 `src/styles/site.css` 中的 CSS 变量，不在单个页面随意引入新颜色：

- `--ink`：主文本和标题。
- `--muted`：摘要、说明和次要文本。
- `--blue`：品牌强调色、链接、当前状态和交互焦点。
- `--line`：边界线和分隔线。
- `--soft`：学习目标、提示和轻量强调背景。
- `--warm`：警告或需要注意的内容。
- `--green`：练习和完成导向内容。

颜色要表达状态或信息层级，不能只作为装饰。背景优先保持白色，避免在不同页面引入不一致的暖灰或渐变背景。

### 主题模式

- 支持三种模式：`日间`、`夜间`、`自适应`。
- 默认使用 `自适应`，跟随操作系统的 `prefers-color-scheme`。
- 用户选择保存在 `localStorage` 的 `aai-learning-color-mode` 中，并在所有页面复用。
- 主题状态统一写在 `<html data-color-mode="light|dark|auto">`，不要在页面中单独添加主题 class。
- 颜色使用语义 token；同一 token 在日间和夜间提供不同值，避免直接写死白色、黑色或灰色。
- 顶部只保留课程切换和主题切换两个控件；品牌标题负责返回课程首页，不再重复放置“全部课程”按钮。
- 课程切换和主题切换统一使用线性 SVG 图标按钮，尺寸、边框、圆角、线宽一致；按钮使用横向矩形，不使用正方形。
- 主题选择器默认显示当前模式图标；展开后使用太阳、月亮、系统屏幕三个图标选择“日间 / 夜间 / 自适应”。图标必须有 `aria-label`、`title` 和键盘焦点状态。
- 夜间模式保持低对比度的深色背景、柔和边框和可读的蓝色强调，避免纯黑背景与刺眼纯白文字。

### 排版

- 主体字体使用系统中文字体栈：`Microsoft YaHei`、`PingFang SC`、`system-ui`。
- 代码使用 `Consolas`、`Cascadia Code` 等等宽字体。
- 页面标题需要明显，但不使用夸张的营销式大标题。
- 正文保持舒适行高，长段落拆成短段落或列表。
- 英文课程名、术语和代码保持原文，中文负责解释含义和使用场景。

### 布局与组件

- 首页课程列表最大宽度约 `760px`，居中显示。
- 课程阅读页使用两栏布局：目录约 `250px`，正文占剩余空间。
- 使用开放式列表、表格和分隔线优先于重复的圆角卡片。
- 交互元素必须有 hover、focus 和 active 状态。
- 品牌标题、课程入口和目录链接必须复用全局交互样式；品牌标题 hover 时使用品牌色，并始终直接返回课程选择首页。
- 所有生成页必须在任何阻塞脚本或样式之前声明固定 `<title>AAI 学习手册</title>`；favicon 使用构建时内联的小型 SVG，避免章节切换时短暂显示文件名和浏览器默认图标。
- 课程目录中的页内锚点使用即时跳转，不播放平滑滚动动画，避免长页面产生等待感。
- 课程目录使用“Module / 章节 → 原始课件分章”的两级结构：只有当前 Module 或章节展开，其他项保持收起。
- 子标题必须遵循来源材料本身的尺度与命名，例如一组 `Chapter 1.1`–`1.8` 课件应分别列为子标题，不能用“术语 / 核心知识 / 常见错误 / 练习”等页面模板区块替代原始课程结构。
- 有明确课件目录时，在 `site.config.json` 对应页面的 `subsections` 中声明原始分章及锚点；只有没有来源目录的自编课程，才回退使用全局 `sections`。
- 当前章节的子标题使用约 `200ms` 的高度、位移与透明度过渡展开；动画只表达层级变化，不延迟章节链接跳转，并必须遵守 `prefers-reduced-motion`。
- 收起的子标题必须同时退出键盘导航和辅助技术浏览，不能只在视觉上隐藏；当前子标题随 URL hash 标记 `aria-current="location"`。
- 展开的子目录必须具有 scroll spy：正文标题经过顶部阅读线时，同步更新左侧高亮与 `aria-current="location"`；用户仅滚动页面时不改写 URL 或浏览历史，点击目录时才更新 hash。
- 箭头、菜单按钮等符号只用于表达导航，不用作装饰图案。
- 不使用常驻的全局左侧课程栏；课程切换统一放在顶部下拉按钮中。
- 新组件优先复用现有 CSS 类和变量，避免在 HTML 内散落内联样式。

## 4. 响应式与可访问性

- `800px` 以下进入移动端布局：阅读页目录改为顶部内容，首页列表保持单列。
- 课程切换按钮必须使用真实 `<button>`，并维护 `aria-expanded` 与 `aria-controls`。
- 导航链接使用清晰的文字，不依赖颜色作为唯一识别方式。
- 表格需要保留表头，代码块和长表格允许横向滚动。
- 不用 hover 才能发现的关键信息；键盘用户应能访问课程链接和目录链接。
- 动画只用于反馈和层级变化，不能妨碍阅读。

## 5. 内容与维护规则

- 课件总结只整理来源材料中能确认的内容，不自行补写课程观点。
- 如果课程有 PPT、演示文稿或导出的课件 PDF，优先从原课件中挑选有教学价值的示例截图，并嵌入对应 Module：优先选择能说明概念、对比差异、展示错误或支撑练习的页面，不截取纯标题页或装饰页。
- 每个有课件来源的 Module 至少评估 2–4 个可复用示例；截图应保留原图表、标题和必要图例，并在页面中标注示例用途与来源章节。
- 课件截图必须适配日间和夜间模式：图片本身保持原貌，外围容器、说明文字和边框使用主题 token；必要时提供足够的 alt 文本，不在图片上叠加低对比度文字。
- 新增术语时同时写出准确解释，不只罗列英文名词。
- 图表、数据和 AI 概念要区分“描述现象”和“证明因果”。
- 每个模块至少提供一个能验证理解的练习。
- 新课程只加入 `site.config.json`，并在 `src/content/` 添加对应正文；首页、课程菜单和左侧目录由构建脚本统一生成。
- 新课程的输出路径在 `site.config.json` 中声明，正文源文件放在 `src/content/courses/` 或对应课程目录。
- 全局样式只维护在 `src/styles/`；Header 和主题交互只维护在 `src/client/header.js` 与 `src/client/theme-init.js`。
- `index.html`、`chapters/`、`courses/` 和 `assets/build/` 是生成结果，不直接编辑，也不手写资源版本号。
- 修改后运行 `pnpm test`；它必须通过页面生成、课程配置、内部链接、锚点和浏览器交互检查。

## 6. 当前组件约定

- `course-row`：首页课程选择行。
- `course-menu`：课程页顶部课程切换按钮与下拉菜单。
- `chapter-layout`：课程内容页的目录 + 正文布局。
- `toc`：当前课程内部目录。
- `chapter-group` / `chapter-subnav`：章节及其可折叠子标题；仅当前章节展开。
- `content-section`：章节中的主要内容区块。
- `terms`：术语或概念对照表。
- `note` / `warning` / `exercise`：提示、警告和练习模块。

除非有明确的交互需求，不要再引入新的卡片体系或重复的导航体系。
