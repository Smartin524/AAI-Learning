CHAPTER 10

迷你 RAG：从文档到可引用答案

RAG 不是单一模型，而是一条数据与推理流水线。完整系统必须处理摄取、切块、索引、查询、召回、提示词、生成、引用、拒答和评估。

学完你应该能够：手写端到端迷你 RAG；理解每一步输入输出；加入引用和拒答；用检索指标与答案指标验证系统。

必须掌握的术语

术语 准确理解
RAG Retrieval-Augmented Generation，检索增强生成。
ingestion 文档进入系统的解析、清洗和索引过程。
chunk 作为检索单位的文档片段。
chunk overlap 相邻片段重复内容，减少边界信息丢失。
retriever 根据查询返回候选证据的组件。
reranker 对候选进行更精细的相关性重排。
context 交给生成模型的检索证据。
grounding 答案被提供证据支持。
citation 答案对应的来源引用。
hallucination 模型生成缺乏证据或错误的内容。
faithfulness 答案是否忠实于检索上下文。
retrieval evaluation 衡量相关证据是否被召回。

1. 端到端结构

文件
  → 解析与清洗
  → 切块 + metadata
  → embedding
  → 向量索引
用户问题
  → query embedding
  → top-k 检索
  → 可选 rerank
  → 组织 context
  → LLM 生成
  → 答案 + 引用

2. 文档数据结构

documents = [
    {
        "chunk_id": "python-01-003",
        "text": "input() 返回字符串。",
        "source": "python_notes.md",
        "section": "Casting"
    }
]

metadata 必须在切块时保留，生成引用时才能回到原文。

3. 切块

def chunk_text(text, size=400, overlap=60):
    if not 0 <= overlap < size:
        raise ValueError("overlap 必须小于 size")
    chunks = []
    start = 0
    while start < len(text):
        chunks.append(text[start:start + size])
        start += size - overlap
    return chunks

固定字符切块便于学习，但真实项目应考虑标题、段落、表格、代码和语义边界。

4. 建索引和检索

import numpy as np

doc_vectors = embed([doc["text"] for doc in documents])
doc_vectors /= np.linalg.norm(doc_vectors, axis=1, keepdims=True)

def retrieve(query, top_k=3):
    q = embed([query])[0]
    q = q / np.linalg.norm(q)
    scores = doc_vectors @ q
    ids = np.argsort(scores)[-top_k:][::-1]
    return [
        {**documents[i], "score": float(scores[i])}
        for i in ids
    ]

5. 构造提示词与引用

def build_prompt(question, hits):
    context = "\n\n".join(
        f"[{i}] 来源：{hit['source']}\n{hit['text']}"
        for i, hit in enumerate(hits, start=1)
    )
    return f"""只根据资料回答。
如果资料不足，请明确说不知道。
引用格式使用 [1]、[2]。

资料：
{context}

问题：{question}
"""

6. 拒答策略

hits = retrieve(question, top_k=3)
if not hits or hits[0]["score"] < min_score:
    answer = "现有资料不足以回答这个问题。"
else:
    answer = generate(build_prompt(question, hits))
相似度阈值不能保证答案正确。它只是一层保护；还需要评估检索相关性、答案忠实度和引用是否真的支持主张。

7. 评估拆成两层

层 问题与指标
检索 正确证据是否进入 top-k？Recall@k、MRR、nDCG。
生成 答案是否正确、忠实、完整、引用准确？人工标注或可信评审。

8. 调试顺序

  1. 先查看切块是否完整可读。
  2. 再查看 top-k 是否包含正确证据。
  3. 然后检查 context 是否超长或顺序混乱。
  4. 最后才修改 prompt 或更换 LLM。

常见错误

  • 把所有问题都归因于“大模型不够好”，不检查检索结果。
  • 切块过大导致主题混杂，过小导致证据残缺。
  • 只显示文件名，不保留页码或章节。
  • 没有“资料不足”的拒答路径。
  • 把检索到的恶意指令当系统指令执行，忽略 prompt injection。
  • 没有测试集，只凭演示问题评价系统。
  • 更新文档后未同步重建索引。

分层练习

基础
  1. 用五段假向量文档完成 top-3 检索。
  2. 为每个结果保留 source 和 score。
进阶
  1. 接入真实 embedding，索引自己的十篇笔记。
  2. 实现带 [1] 引用和无证据拒答的回答。
掌握标准
  1. 创建至少 30 个问题的评估集，计算 Recall@3。
  2. 比较两种 chunk size、top-k 和是否 rerank。
  3. 写一页误差分析：检索失败、生成失败、数据失败分别占多少。
