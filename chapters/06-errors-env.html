CHAPTER 06

异常、模块、包与虚拟环境

可靠程序必须明确失败方式。你需要读懂 Traceback、只捕获预期异常、组织模块，并用虚拟环境保证依赖可复现。

学完你应该能够：系统阅读 Traceback；正确使用 try/except/else/finally 和 raise；理解模块导入、venv、pip 与 requirements。

必须掌握的术语

术语 准确理解
exception 运行时发生的异常对象，会沿调用栈向上传播。
Traceback 异常发生前的函数调用路径。
raise 主动抛出异常。
try / except 包围可能失败的代码并处理特定异常。
else / finally 无异常时执行；无论是否异常都执行。
module 一个可导入的 Python 文件。
package 组织多个模块的包。
dependency 项目依赖的外部软件包。
virtual environment 隔离 Python 解释器与依赖安装位置。
version pinning 固定依赖版本以提高复现性。

1. 阅读 Traceback

先看最后一行，确定异常类型和消息；再从下往上找第一处属于你项目的文件和行号；最后检查传入该行的数据。 

Traceback (most recent call last):
  File "app.py", line 12, in <module>
    top_k = int(raw)
ValueError: invalid literal for int() with base 10: 'abc'

2. 捕获具体异常

from pathlib import Path
import json

try:
    text = Path("config.json").read_text(encoding="utf-8")
    config = json.loads(text)
except FileNotFoundError:
    config = {"top_k": 5}
except json.JSONDecodeError as error:
    raise ValueError(f"配置文件不是合法 JSON：{error}") from error
else:
    print("配置加载成功")
finally:
    print("配置阶段结束")

不要使用空的 except:。它会把 KeyboardInterrupt 等也吞掉，让程序看似继续、实际状态错误。

3. 主动验证和自定义消息

def validate_top_k(top_k):
    if not isinstance(top_k, int):
        raise TypeError("top_k 必须是 int")
    if top_k <= 0:
        raise ValueError("top_k 必须大于 0")

5. 虚拟环境和依赖

# Windows PowerShell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install numpy requests pytest
python -m pip freeze > requirements.txt
API Key 应放环境变量或本地 .env，并把 .env 加入 .gitignore。永远不要提交真实密钥。

常见错误

  • 用 except Exception: pass 吞掉所有错误。
  • 把过大代码块放进 try，无法判断是哪一步失败。
  • 使用错误的 Python 解释器安装包，导致“已安装但无法 import”。
  • 直接运行包内部文件导致相对导入错误。
  • requirements 不固定关键版本，换机器后结果不同。
  • 把 .venv 或 API Key 提交到 Git。

分层练习

基础
  1. 分别触发并识别 NameError、TypeError、ValueError、KeyError。
  2. 安全读取一个可能不存在的 JSON 文件。
进阶
  1. 把迷你 RAG 拆成 chunking.py 和 retrieval.py。
  2. 创建干净 venv，仅用 requirements 重装依赖。
掌握标准
  1. 根据完整 Traceback 解释异常传播路径。
  2. 设计错误策略：哪些异常重试、哪些拒答、哪些立即终止。
